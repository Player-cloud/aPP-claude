| DEC-022 | **M7 quality gate and ship-check: deterministic gates over evidence the app recorded, release preparation only.** A release names a version, the completed work it includes, release check commands and a plan (target, health check, rollback; monitoring, migrations and configuration names optional). | DEC-026 | **M10 Iterative Layer, observe and recommend: a self-assessment of the app's own records and an improvement backlog that only the person moves.** The self-assessment reads workflow runs (blocked, failed), agent tasks (failed, timed out, permission denied, blocked), builds (abandoned, completed with accepted risks other than the always-present manual check), build and release check runs (timed out, could not run), repository assessments (failed), the latest tool scan (confirmed and release-blocking findings) and spend (80% of the monthly budget or more). Each finding is reported in three layers: the observation (a count and the linked records), the inference (a likely cause with low, medium or high confidence) and the recommendation (title, problem, expected outcome, success criteria, priority, risk). It also lists what the app does not record (crashes, screen response times, resource use, satisfaction beyond typed feedback, integrations), and reads only ids, timestamps, short redacted labels and error summaries: no source code, prompt bodies or credentials. Each finding has a stable signature; the first time it becomes a *proposed* item, and later runs add only records not seen before as evidence on the same item (following merges). Typed feedback becomes an *idea*. Statuses: idea → proposed (needs problem, expected outcome, success criteria) → approved (records the OS user as approver; the definition is then fixed) → in progress (needs dependencies released) → verified (needs a result) → released (needs a measured outcome; final), plus blocked (needs a reason, returns where it was) and rejected (needs a reason, can be reopened as an idea with a reason). Going back before approval clears the approval. Items are never deleted (trigger); a duplicate is merged, which links it and moves its evidence. For detector items the app counts occurrences after approval from the latest self-assessment. Self-assessments are frozen. Approving changes nothing in the app: building an approved improvement through the Project Layer is FR-ITER-003, later | Adopted (joshua chose M10: Self-assessment + improvement backlog, 2026-10-28) | Ask Claude to analyse the records; automatic status moves; collect detailed telemetry (timings, crash reports) first | Free, deterministic and testable from records the app already keeps. Thresholds are simple counts, so the inferences are deliberately modest and say how sure they are. Telemetry the app lacks is named instead of guessed |
